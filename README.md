> A portfolio project where I built the RAG pipeline end to end: **clinical-note preprocessing → chunking → embeddings → vector search → grounded LLM response**.

## 📌 About

This repository is my implementation of a clinical-notes RAG workflow. I wanted to understand what happens between a user's question and an LLM answer, so I separated the system into clear stages instead of hiding the whole process inside one script.

The current flow is:

**JSON clinical notes → cleaning → text chunks → sentence embeddings → Pinecone → similarity retrieval → Gemini → Streamlit chat UI**

## 🔄 RAG Pipeline

### 1. Data cleaning

`clean_files.py` walks through the dataset recursively and keeps the clinical-context fields used by the application:

- Admission / chief complaint
- Patient history
- Past medical history
- Family history
- Physical examination
- Labs and imaging

Empty values are skipped, and each record is written as a cleaned text file.

### 2. Chunking

`ingestion.py` splits the cleaned notes into overlapping chunks:

- **Chunk size:** 800 characters
- **Chunk overlap:** 400 characters
- **Start-index metadata:** enabled

The overlap is intentional so details near a chunk boundary are less likely to be separated from their surrounding context.

### 3. Embeddings

The project uses `sentence-transformers/all-MiniLM-L6-v2` through LangChain/Hugging Face to turn each chunk into a **384-dimensional vector**.

### 4. Vector storage

Embeddings are stored in **Pinecone** using **cosine similarity**. Chunk IDs are derived from source information, position and content so indexing stays predictable across runs.

### 5. Retrieval

`retrieval.py` provides a small, separate way to inspect the retrieval layer. The application uses similarity-score filtering and returns the most relevant chunks for the current query.

### 6. Generation

`chatbot_rag.py` sends the user's question together with retrieved clinical-note context to **Gemini 2.5 Flash**. The prompt asks the model to stay within the supplied context instead of treating the LLM as an unrestricted knowledge source.

### 7. User interface

Streamlit provides the chat interface and exposes the retrieved source snippets so the response can be inspected against the retrieved context.

## ⚙️ Setup

### Requirements

- Python 3.9 or newer
- Pinecone API key
- Google Gemini API key

### Clone

```bash
git clone https://github.com/mohdsaif13/RAG-clinical-notes.git
cd RAG-clinical-notes
```

### Virtual environment

Windows:

```bash
python -m venv venv
venv\\Scripts\\activate
```

macOS / Linux:

```bash
python -m venv venv
source venv/bin/activate
```

### Install packages

```bash
pip install -r requirements.txt
```

### Environment variables

Create a local `.env` file:

```env
PINECONE_API_KEY=your_pinecone_api_key
GOOGLE_API_KEY=your_gemini_api_key
PINECONE_INDEX_NAME=medical-rag-hf
PINECONE_NAMESPACE=
PINECONE_RESET_NAMESPACE=true
```

Optional Pinecone settings:

```env
PINECONE_CLOUD=aws
PINECONE_REGION=us-east-1
```

Do not commit `.env` or API keys.

## ▶️ Run the Pipeline

From the repository root:

### Clean the source notes

```bash
python clean_files.py
```

### Build the Pinecone index

```bash
python ingestion.py
```

### Check retrieval

```bash
python retrieval.py
```

### Start the app

```bash
streamlit run chatbot_rag.py
```

Open the local Streamlit URL shown in the terminal, normally `http://localhost:8501`.

## 🔍 Engineering Notes

- The embedding model is intentionally lightweight, making local experimentation practical.
- Chunk overlap is used to preserve nearby context.
- Retrieval and generation are separated so each layer can be tested independently.
- API credentials are read from environment variables rather than source code.
- The application shows retrieved source snippets to make the generated answer easier to inspect.

## ⚠️ Limitations

This is a learning and portfolio project, not a clinical system.

- Retrieval quality depends on the dataset, chunking strategy and embedding model.
- Retrieved text can still be incomplete or irrelevant.
- An LLM can produce an incorrect or incomplete response even with retrieved context.
- There is no clinical validation or medical decision-support approval.
- The application must not be used to diagnose or treat patients.

## 🔐 Data & Security

Keep dataset access, licensing and redistribution requirements in mind. Do not upload private patient information, secrets or API keys.

`PINECONE_RESET_NAMESPACE=true` is enabled by default in the current ingestion script, so rerunning ingestion clears the configured namespace before rebuilding it.
